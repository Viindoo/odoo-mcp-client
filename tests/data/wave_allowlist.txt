# The `wave` GROUPING LAYER is deleted, not renamed: a plan is a flat DAG of
# work NODES joined by `depends_on`, and NOTHING groups nodes. The guard
# `test_the_word_wave_never_regrows_outside_the_allowlist` therefore fails on
# the word-boundary token `wave` / `waves` (any case, hyphen and camelCase
# compounds included) anywhere under `plugins/`, `tests/`, `docs/` and the
# repo-root `*.md` files, except `CHANGELOG.md` and `ROADMAP.md` (release
# history is a record of what happened and stays).
#
# FORMAT - one entry per line:   <repo-relative path>: (<sense>) <reason>
#   - the path is split off at the FIRST colon;
#   - `<sense>` is one or more of the five ALLOWED SENSE letters below, each
#     parenthesised, e.g. `(a)` or `(d)(e)`;
#   - an entry whose reason names no allowed sense FAILS the test;
#   - an entry whose file no longer holds the token FAILS the test too, so a
#     stale exemption cannot outlive the text that earned it.
#
# ALLOWED SENSES (SSOT for the letters: ALLOWED_SENSES in the test module)
#   (a) development-milestone narration - "the M9 wave", "wave-13 files",
#       "a prior wave renamed X": a delivery round, never a plan-node grouping.
#   (b) the WMS domain term "wave picking" - a real Odoo warehouse feature.
#   (c) the English idiom - "waved through", "hand-waved", "wave it through".
#   (d) a legacy on-disk key or path that must still be READ for backward
#       compatibility (a pre-rename state dir, a pre-rename ledger key).
#   (e) guard subject - the token is the subject of an assertion that BANS it,
#       or appears in that assertion's own rationale / scanned pattern.
#
# Anything else is regrowth. Fix the text; do not add a line here.
# ============================================================================
